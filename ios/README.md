# ios/

The umbrella for the native iOS CDS package. It holds **no source code** — only an Xcode
**workspace** that opens the two Swift modules together, mirroring how `android/` is the umbrella
for the two Kotlin modules.

Those modules live where Nx expects them, not here:

| Module              | Directory           | Nx project    |
| ------------------- | ------------------- | ------------- |
| `CDSDesignSystem`   | `packages/cds-ios/` | `cds-ios`     |
| `CDSGalleryiOS` app | `apps/ios-gallery/` | `ios-gallery` |

`CDS.xcworkspace` references both so Xcode shows them as peers — you edit the real files in
`packages/` and `apps/`, not copies.

## Why this umbrella is lighter than `android/`

Gradle needs a single settings root (`settings.gradle.kts`) to span multiple modules, so
`android/` is a real build root with a wrapper and version catalog. SwiftPM has **no equivalent** —
a Swift package is self-rooted, and a package's target sources must live inside the package folder
(they cannot be remapped to a sibling directory the way Gradle's `projectDir` allows). So there is
nothing to put here but a workspace that ties the two independently-buildable modules together for
editing.

## Opening in Xcode

The app project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) and is
git-ignored, so generate it once before opening the workspace:

```sh
yarn nx run ios-gallery:build # runs `xcodegen generate` (among other things)
# or: (cd apps/ios-gallery && xcodegen generate)

open ios/CDS.xcworkspace
```

The workspace shows `cds-ios` (the theme library) and the `CDSGalleryiOS` app side by side. Pick
the **CDSGalleryiOS** scheme and a simulator to run the gallery.

## Building

From the **repo root**, through Nx or straight to the toolchain:

```sh
yarn nx run cds-ios:test       # swift test (theme library)
yarn nx run cds-ios:build      # swift build -c release
yarn nx run ios-gallery:build  # xcodegen + xcodebuild (iOS Simulator build)
yarn nx run ios-gallery:launch # build + install + run the gallery on a Simulator

(cd packages/cds-ios && swift test)
```

The root CI orchestrator calls [`.github/workflows/ios.yml`](../.github/workflows/ios.yml) when
Xcode paths change. That reusable workflow runs on macOS with Swift and Xcode.
