# CDS Icons Contributing Documentation

## Icon Font

Note on unicode character points:

Our custom icon font is generated by mapping each unique icon SVG to a unicode code point in the unicode Private Use Area. We use the inclusive unicode range `0xF0000` - `0xFFFFD` (`983040` - `1048573`) in the Private Use Area of plane 15. This range includes 65534 unique unicode points, so there is a limit of 65534 icons per font. We avoid using the Basic Multilingual Plane to prevent our icons from falling back to emojis while loading on iOS.

## Syncing Icons

The **Sync Figma Assets** workflow runs this sync: from the Actions tab (choose `icons`) or on its weekday schedule. The sync only writes the generated files and a report. The workflow commits them on a new `icons/YYYY-MM-DD` branch, writes the version plan from the report (it lists the added, updated, renamed and deleted icon sets, and selects `major` when any was renamed or deleted and `minor` otherwise), applies it with `yarn release --projects=icons` unless the sync is breaking, and pushes the branch. The Slack message that ends the run links to the pull request form for that branch, with the title and description filled in. Open it, then review it as described below. Squash-merge it: the workflow's commits are not signed.

**IMPORTANT: If any icon sets are renamed or deleted, this is a BREAKING CHANGE. This MUST be published with an accompanying major version bump, migration guide, and a migrator script. The workflow does not release a breaking sync; it keeps the version plan, and you run `yarn release --projects=icons` on the branch once the migration guide and migrator are ready.**

### Running the sync locally

1. Retrieve the team Figma API key from the Config Service and set it in your environment.

```sh
export FIGMA_ACCESS_TOKEN=VALUE-FROM-CONFIG-SERVICE
```

2. Install dependencies

```sh
nvm use
yarn install
```

3. Run the icon sync. It writes the generated files into your working tree, and nothing else: no branch, commit, version plan, release or push. Review the result with `git diff`

```sh
yarn nx run icons:sync-icons
```

> As part of the sync, `sync-icons` also regenerates the Figma Code Connect mappings by calling `sync-icon-code-connect`. This writes a single [Code Connect batch integration](https://developers.figma.com/docs/code-connect/batch-files/) per package — a shared `icons.figma.batch.ts` template plus an `icons.figma.batch.json` listing every icon — into `packages/web/src/icons/__figma__/` and `packages/mobile/src/icons/__figma__/`, replacing any previously generated files. It can also be run on its own:
>
> ```sh
> yarn nx run icons:sync-icon-code-connect
> ```

4. When any icon changed, the sync also writes the version plan into `.nx/version-plans`. It selects `major` when an icon was renamed or deleted, and `minor` otherwise.

To publish in the same branch, release as usual:

```sh
yarn release --projects=icons
```

### Reviewing the sync pull request

1. DM the icons DRI on Slack and share direct links to:

- the icon changelog in your PR
- the Web Visual Regression results in Percy

You can get the Percy link from the GitHub Actions "Visreg Web" job on your PR

2. Carefully review the two links you shared with the icons DRI. Does the changelog look correct? Do the visual regression results look correct?

**IMPORTANT: Breaking change releases are a big deal. They should be performed extremely rarely, and should ALWAYS be accompanied by a migration plan. You are responsible for any breaking changes that you release.**

3. DO NOT MERGE until the icons DRI has carefully reviewed and signed off on the changelog and the visual regression test results.

### Syncing Icons Troubleshooting

**"There are no changes since the last update on XX/XX/XXXX"** — The script detected no icon changes in Figma since the last sync. Verify this is expected with design.

**Force a full re-sync** — If you need to re-sync all icons regardless of when they were last updated, pass the `--sync-all` flag:

```sh
yarn nx run icons:sync-icons -- --sync-all
```
